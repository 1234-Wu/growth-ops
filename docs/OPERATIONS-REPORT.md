# 运营数据：执行、增长与内容效果

三个视图回答不同问题。底层的actions、tasks和metrics保留原样，旧累计快照不会被改写成日增长。

## 1. 每日执行

按动作实际发生的北京时间日期统计：原创发布数、发出回复数、其他已记录动作、实际完成的任务。发出回复包含账号自身线程补充；不等于别人给账号的回复。

任务完成日期取明确记录的 `data.completed_at`（或已保存的完成日期），不能用截止时间、导入时间或更新时间替代。历史任务虽标为完成但缺少实际完成时间时，不伪造某天的完成数量。

柱状图只展示执行数量，不放浏览、点赞、收藏等累计指标。没有已登记动作不保证平台当天没有动作。

## 2. 每日增长

横轴为指标实际统计区间所属日，不是内容发布日期。优先使用账号/产品的日区间记录；仅在严格满足条件时使用累计快照差值。

### 日区间记录

使用现有metrics API保存：

```json
{
  "title": "账号每日浏览量",
  "account_id": "<account-id>",
  "product_id": null,
  "data": {
    "metric_name": "views",
    "metric_type": "interval",
    "value": 120,
    "availability": "valid",
    "period_start": "2026-09-10T00:00:00+08:00",
    "period_end": "2026-09-11T00:00:00+08:00",
    "observed_at": "2026-09-11T09:00:00+08:00",
    "observed_at_precision": "minute",
    "source": "实际日报来源，附核验说明"
  }
}
```

示例数值只说明接口格式，不是本项目真实数据。统计边界必须是北京时间连续两天的零点；observed_at是采集时间，可以晚于区间结束。指标名为views、likes、replies、bookmarks、net_followers。净增粉丝可以为负；未知用availability标记且value=null。

账号级日区间记录不关联单条action_id/content_id。多个来源覆盖同一区间时不相加，优先选择有效的最新记录并保留来源；再按账号或产品汇总。

### 快照差值

- 相同账号、对象、指标、数据来源，两个有效累计快照的实际观测时间恰好覆盖北京时间连续零点边界，才计算这一日的差值。
- 仅有日期、以00:00作排序锚点的旧快照不可参与；缺测、隔了多日或时间窗不同，不按天平均、不插值、不强行差分。
- 当前增长视图只使用账号/产品级指标；单条内容快照只用于内容表现，不参与账号每日增长，避免把部分内容覆盖冒充账号全量。
- 浏览、点赞、收到回复或收藏发生负差值时，不截断成0；标记异常/不可用。粉丝差值可为负。
- 不为当天新发布但缺少起点快照的内容虚构0基线。

当前历史资料主要是非固定时刻的累计快照，因此每日增长视图可能没有可用点。缺失显示“—”、折线断开；不画虚假的零增长线。

## 3. 内容表现

每条实际帖子或回复一行，保留产品/账号归属、发布时间、指标采集时间与观测窗口。

- 默认比较发布后24小时，可切换72小时、7天或最新累计。
- 固定窗口只使用观测时间位于“精确发布时间+窗口”前后30分钟内的累计快照；挑选最接近目标时刻的有效采样，展示实际内容年龄。不是把“第二天”统一称为24小时。
- 发布时间或采集时间只有日期、窗口尚未到达、窗口内没有采集，均不从更晚的累计值补数。
- 各指标有自己的采集时间，不能把一次浏览量采样的时刻套给所有其他指标。
- 排行榜使用当前选择窗口的浏览量；没有该窗口数据的内容不参与排名。历史资料可用“最新累计”查看，但不能以此宣称同年龄效果比较。
- 删除的内容保留历史标记，不参与仍公开内容的排行榜。

同一账号的同一外部内容ID去重，不能跨账号误合并。业务操作量与收到的互动量是不同指标。

## API与维护

认证GET `/api/v1/reports/operations`：

- `view=execution`：每日执行。
- `view=growth`：每日增长，日期为统计区间所属日。
- `view=content&window=24h|72h|7d|latest`：内容效果；日期筛选为内容发布日期。
- 共有参数：account_id、product_id、date_from/date_to（YYYY-MM-DD）、limit/offset。内容还可用type=publish|reply和q筛选。
- 旧 `view=daily` 作为 `execution` 的别名，仅返回执行统计，不再提供按发布日期汇总的累计效果。内容接口缺省窗口继续使用latest，新UI明确发送24h。

图表从完整筛选范围生成，表格仍每页10条。超长图表范围有明确截断提示。原始记录入口保留数据录入与核验功能；原始指标表新增了区间边界和观测精度字段。
