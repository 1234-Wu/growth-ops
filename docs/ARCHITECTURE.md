# 架构与边界

## 使用方式

外部 AI 负责规划、执行、数据采集、分析和复盘；本项目只负责 API、SQLite 持久化、确定性统计和网页管理。系统不会调用模型，不自动登录社交平台，不执行保存在 Skills 中的代码，不自动发布内容。

各模块有独立页面。仪表盘只展示关键数据与统计，可下钻记录；任务、动作、内容、监测、数据、策略、复盘、知识、Skills、账号和产品分别管理。

## 运行结构

- `server.py`：Python 标准库 HTTP 服务、API、校验、SQLite、鉴权与静态文件。
- `api_schema.py`：机器可读 OpenAPI 契约。
- `web/`：React + TypeScript + shadcn/ui 前端，Next.js 静态导出至 `web/out/`。
- `static/`：保留旧原生界面作为显式回退。
- `data/`：首次运行创建，存储数据库和本地 API Key。不要提交到代码库。
- `tests/`：隔离数据目录中的自动化验证，不写真实运营数据。
- `skills/growth-ops-recorder/`：外部 AI 的接入规则及参考文档。

## 核心关系

平台关联账号，产品为独立维度。策略、任务、动作、指标、复盘通过 ID 引用。`data` 保存模块专属字段，可附加来源、证据、策略版本和内容版本；顶层归属字段用于筛选。

一个账号可以关联多个产品，一项产品可以通过多个账号推广。当前为单工作空间、单持有人密钥的本地应用。不同账号是业务筛选维度，不是多租户安全边界；密钥持有人可管理整个实例。

## 数据语义

实际动作与计划任务分开。一次动作的指标可有多个观测时间，保留来源和累计/区间口径。指标缺失不填零，累计快照不相加。归因是外部 AI 或操作者提交的判断，系统不为其正确性背书，也不自动把一个账号当日增长分配给某个动作。

策略与 Skill 的版本历史支持追溯；动作应同时存 `strategy_id` 和 `strategy_version`。后续任务的 `review_id` 与后续动作的 `parent_action_id` 构成迭代链。

## 运维范围

默认只监听本机。远程 AI 需要能访问服务地址；正式跨设备使用应在可信网络或带 HTTPS 的反向代理后部署，并配置访问控制和备份。内置 HTTP 服务用于本地/可信环境，未宣称完成互联网生产部署或多人权限隔离。

监测页面存储到期事项；由外部 AI 的调度系统决定何时查询并执行采集。本应用不提供后台采集器。

网页导出用于可读迁移；数据库备份用于完整恢复版本和幂等状态。恢复前先验证目标实例为空，并在临时目录做恢复演练。附件首版保存引用/链接或记录正文，不提供二进制文件上传存储。

新版页面不需要独立 Node 服务常驻，Python 优先提供 web/out 静态文件。未构建时或 GROWTH_LEGACY_UI=1 时回退旧界面。
